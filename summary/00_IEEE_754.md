# IEEE 754에서 float 타입의 exponent에 127이 보정으로 더해지는 이유

IEEE 754에서 지수부를 그냥 2의 보수(signed)로 저장하지 않고 바이어스(bias) 127을 더한 값(biased exponent)으로 저장하는 이유는, 부호 없는 정수처럼 비교할 수 있게 하기 위함이다.

### 핵심 이유: 크기 비교를 정수 비교로 처리
지수는 음수(예: 2⁻³)도 표현해야 하는데, 이를 2의 보수로 저장하면 비트 패턴이 아래와 같다.

- 지수 +1 → `00000001`
- 지수 -1 → `11111111`

부호 없는 정수로 보면 -1이 +1보다 훨씬 커 보인다. 그러면 두 float의 크기를 비교할 때 지수부를 따로 부호 있는 수로 해석해야 한다.

바이어스 방식에서는 지수 범위 -127~+128을 0~255로 평행이동시킨다.

- 지수 -1 → 126 → `01111110`
- 지수 +1 → 128 → `10000000`

지수가 클수록 저장된 비트 값도 항상 커지므로, 부호 비트만 같다면 float의 비트 패턴 전체를 정수(int)처럼 비교해도 대소 관계가 그대로 유지된다. 하드웨어에서 비교기를 단순하게 만들 수 있고, 정렬 같은 작업에서도 유리하다.

### 왜 하필 127인가?
float의 경우 지수부가 8비트이므로 저장 가능한 값은 0~255. 여기서 양쪽 끝을 특수 값에 예약한다.

- `0` (00000000): 0과 비정규수(denormal)
- `255` (11111111): 무한대(∞)와 NaN

따라서 정규수에 쓰는 범위는 1~254이므로, 이를 0 중심으로 거의 대칭을 맞추면 127이 바이어스가 된다.

- 실제 지수 = 저장값 − 127 → 범위 -126 ~ +127

참고로 double은 지수부가 11비트라 바이어스가 2¹⁰ − 1 = 1023이다.

### 부가 효과
- 모든 비트가 0인 패턴이 +0.0이 되어 자연스러워 진다.
- 지수가 가장 작은 수가 `0` 쪽에, 가장 큰 수가 `255` 쪽에 와서 비정규수·무한대 처리가 깔끔해진다.

### 예시
12.5 = 1.5625 × 2³ 이므로 실제 지수는 3, 저장되는 지수는 3 + 127 = 130 (`10000010`)
